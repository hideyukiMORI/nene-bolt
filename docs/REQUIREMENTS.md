# 要件と施主の決定 — NeNe Bolt

> Status: normative（規範）/ 2026-10-27 初版
> 施主（hide）が言ったこと・決めたことと、施主が「推しで」と任せたことだけを書く。**施主が言っていない大きな機能を要件に書かない・実装しない。**
> 細かい演出の判断は Q12 のとおり派手な方へ寄せてよい。施主から後で違う指示が来たら、それに従って変え、ADR で置き換える。

NeNe Bolt は、WSL2 の Ubuntu の端末（Windows Terminal）で、手作りの AI のランナーが横スクロールのアクションゲームを自動で遊び続けるスクリーンセーバーである（Swift 製）。
**キーを押すと、その瞬間から人が操作して遊べる。** TITLE → PLAY → GAME OVER（か ENDING）→ TITLE を、`q` を押すまで繰り返す。

施主の依頼の要旨は「NeNe Swarm と同様な感じで、昔のアクションゲーム 2 本（撃って進む横スクロールと、踏んで跳ねる横スクロール）を参考にしたゲームを自動プレイするスクリーンセーバー。
今度はプレイできるようにして。4 面くらいで最後にボス戦」「参考の 1 本の、結晶の洞窟のステージみたいだといい」「消える足場は作りたい」
（元の言葉には実在のゲームと面の名前が入っているので、ここでは要旨にした。CNF-023）。

兄弟の NeNe Gambit・NeNe Reversi・NeNe Igo・NeNe Poker・NeNe Swarm と同じ形（サイバー HUD・12 テーマ・4 名のキャストの減らず口・`install.sh` / `install.ps1`）で作る。
施主の方向づけは Swarm と同じく**派手でモリモリ**（Q12）。

🔴 **兄弟との違い**: (1) 人が遊べる（キーで割り込む）。(2) 横スクロールで、盤面が端末より広い。リアルタイムであること・Core と Engine が時計を知らないことは Swarm と同じ。

## 1. 要件（FR）

| ID | 要件 |
| --- | --- |
| FR-01 | 端末に横スクロールのアクションゲームを描く。自機（ランナー）は左右に走り、跳び、撃つ。画面は自機に合わせて横に流れる |
| FR-02 | **動き**: 走る・跳ぶ（押している長さで高さが変わる）・撃つ（画面に 3 発まで）・溜め撃ち（引き金を溜めると大きな弾）・敵を上から踏んで倒す・梯子を上り下りする |
| FR-02a | **4 つの面**（推し）: 1 草原・2 結晶の洞窟（滑る床・梯子と縦に登る区間・消える足場・青と水色の色合い）・3 空中の足場（動く足場・落ちる穴）・4 要塞（ベルトコンベア・棘・消える足場）。面の途中に中間地点。1〜3 面は旗のゴール、**4 面の終わりにボス戦** |
| FR-02b | **消える足場**（施主決定）: 決まった間隔で順に現れては消える足場。乗っている間に消えると落ちる。並びと間隔は面ごとに決め、毎回同じ（覚えて渡るもの） |
| FR-02c | **ボス**: 4 面の終わりの部屋で戦う大きな敵。体力のゲージを持ち、何種類かの攻撃（跳ぶ・撃つ・突進・画面全体の一瞬の閃光）を順に混ぜる。倒すと ENDING |
| FR-02d | **体力と残機**: 自機は体力のゲージ（被弾で減る）と残機を持つ。穴と棘は 1 回で 1 機失う。体力が尽きても 1 機失う。全部失ったら GAME OVER |
| FR-02e | **拾うもの**: コイン（100 枚で 1UP）・体力の回復・1UP・**パワーアップ**（撃つ弾が強くなる。被弾すると 1 段戻る） |
| FR-02f | **敵**: 歩く・跳ねる・飛ぶ・撃ってくる砲台・面に合わせた変わり種（結晶の洞窟は、近づくと割れて小さく分かれる敵など）。踏めるものと踏めないものがある |
| FR-02g | **ハイスコア**: 上位 5 件（得点・ランナー名か PLAYER・到達した面・難易度）を TITLE と HUD に出し、ファイル（`$XDG_STATE_HOME/nene-bolt/`、無ければ `~/.local/state/nene-bolt/`）に残す。読み書きは合成ルートだけ。読めない・書けないときは起動中だけ（Swarm と同じ） |
| FR-02h | **派手な演出**: 多層の背景のスクロール・爆発・得点の表示・ボス戦の前の警告の帯・面の始まりと終わりの大きな文字の帯・溜め撃ちの光り・ボスの閃光 |
| FR-03 | **場面**: TITLE → PLAY → GAME OVER → TITLE。ボスを倒したら GAME OVER の代わりに ENDING → TITLE。閉じた enum で巡る |
| FR-04 | **自動プレイ**: ふだんは AI のランナーが遊ぶ。穴・棘・敵の弾・消える足場を見て避け、敵を撃つか踏む。完璧ではなく、いつか必ず落ちる（か、ボスを倒す） |
| FR-04a | **人が遊ぶ**（施主決定）: 遊びのキー（←→↑↓・跳ぶ・撃つ）のどれかを押した瞬間から人の操作になる。30 秒何も押さなければ AI に戻る。HUD に誰が操作しているかを出す。人が遊んでいる間もスクリーンセーバーの `q` `t` `d` は効く |
| FR-04b | **キー入力**: Windows Terminal では押す・離すの両方を受け取る（押しっぱなしで走り続け、離すと止まる）。受け取れない端末では、キーのくり返しを「押している」とみなす簡易な操作に落とす。どちらで動いているかを HUD に出す |
| FR-05 | **毎回違うゲーム**: 面の地形は決まっていて、敵の出方・ランナーの迷い・ボスの攻撃の順をシード付きの乱数で変える。同じシード・キー入力なしなら同じゲームと同じセリフ |
| FR-06 | **ランナーは 4 名（性格）**で、ゲームごとに 1 名が走る。性格で走り方・撃ち方・踏み方が変わる。セリフは 1 人 50 本・英語・ウィットに富んだブラック（Swarm と同じ） |
| FR-07 | 自機・敵・弾・地形・拾うものは文字ではなく、**地とは別の色で塗った偶数桁のブロック**で描く。形はこのリポジトリで新しく描き、元のゲームの絵を写さない |
| FR-08 | `q` で終了する。どんな終わり方でも端末を必ず元に戻す |
| FR-09 | 動作環境: WSL2 の Ubuntu＋Windows Terminal。入れ方は兄弟と同じ（`install.sh` と `install.ps1`） |
| FR-10 | HUD: スコア・1 位・面・残機・体力のゲージ・コイン・パワーアップの段・難易度・ランナー（名前と顔）か PLAYER・キー入力の方式・通算のゲーム数 |
| FR-11 | 刻みの速さ・TITLE と GAME OVER を見せる時間・AI に戻るまでの秒数は起動オプションで変えられる |
| FR-12 | 12 テーマは兄弟の 12 種類を引き継ぐ。面ごとの地形の色は、面の色合い（結晶の洞窟は青と水色）をテーマに合わせて決める（ADR で） |
| FR-13 | カラーテーマは実行中のキー `t` で切り替え、起動時は `--theme <名前>` |
| FR-14 | 難易度は EASY / NORMAL / HARD の 3 段階。実行中のキー `d` で巡り、起動時は `--difficulty <名前>`。変えるのは敵の側（数・速さ・弾・ボスの体力）だけで、ランナーの腕は変えない |
| FR-15 | キーのヘルプを画面に常に出す（スクリーンセーバーのキーと、遊びのキー） |
| FR-16 | 画面は兄弟の B 案（罫線の枠・2 段の配置・罫線が 2 桁で描かれる端末では ASCII の枠）。80 × 24 に入る |
| FR-17 | **登録商標のゲーム名・キャラクター名・面の名前・会社名を、製品名・README・コード・セリフのどこにも書かない**（CNF-023 で機械が見る） |

## 2. 施主の決定（2026-10-27）

| # | 論点 | 状態 |
| --- | --- | --- |
| Q1 | アプリ名 | **決定**: NeNe Bolt（`nene-bolt`）。元のゲームの名前は商標なので使わない（FR-17） |
| Q2 | 公開範囲とライセンス | **決定**（兄弟と同じ）: PUBLIC・MIT |
| Q3 | 人が遊ぶのと自動プレイ | **決定**: キーで割り込む（FR-04a）。30 秒で AI に戻る。Windows Terminal では押す・離すを受け取り、だめな端末は簡易な操作（FR-04b） |
| Q4 | ゲームの中身 | **決定**: 2 本の良いとこ取り（走る・跳ぶ・撃つ・溜め撃ち・踏む・コイン・パワーアップ）。4 面で、4 面の終わりにボス（FR-02〜02c） |
| Q5 | 面の雰囲気 | **決定**: 参考の 1 本の「結晶の洞窟」の面のような感じ（青と水色・滑る床・梯子・縦に登る区間）を 2 面の主題にする |
| Q6 | 消える足場 | **決定**: 入れる（FR-02b） |
| Q7 | 進め方 | **決定**: NeNe Swarm と同じ。統合リナがこのセッションで厳格規約で実装し、推しで自走する。キャスト 4 名・セリフ・12 テーマ・難易度・ハイスコアも Swarm と同じ |
| Q8 | 道具の導入・PR | **決定**（兄弟と同じ）: 開発用の道具は確認なしでよい。フルゲートが緑なら Ready・squash merge・Issue の起票は確認なしでよい。**Release の公開など外に出る操作は施主の確認を取る** |
| Q12 | 残りの判断の寄せ方 | **決定**（Swarm と同じ）: 派手でモリモリになる方へリナの判断で寄せる。寄せて決めたことは ADR に書き、区切りの報告で施主に知らせる。規約とゲートを弱めない・文字の読みやすさのテストを通す・80 × 24 に入る・元のゲームの名前や絵を写さない |
| Q13 | 1 ゲームの長さ（推し） | 自動プレイの NORMAL で平均 4〜6 分（4 面まで行けるのは時々）。計測して ADR に書く |

**施主に聞いてから決めること**: 音（端末のベル）・既に決めた FR を削ること・人が遊ぶ操作のキー配置を大きく変えること。

## 3. 不変条件（テストで守る）

- **決定性**: 同じシード・同じ入力の列からは、同じ状態の列とセリフの列になる
- **範囲**: 自機・敵・弾は面の中（か、画面の外へ出て消える途中）にある。自機は地形に埋まらない（どの刻みでも、固い地形のセルと重ならない）
- **当たり判定**: 速く落ちても床を突き抜けない（1 刻みで飛び越えない）。踏む・撃つ・触れるの結果が手で作った場面で決まったとおりになる
- **消える足場**: 決まった間隔どおりに現れて消える。消えている間は乗れない。乗っている間に消えたら落ち始める
- **数の保存**: スコアは減らない・増えた分は出来事の得点の合計。残機は失った出来事と 1UP の出来事でだけ動く。コインは 100 枚で 0 に戻って 1UP
- **場面の遷移**: TITLE → PLAY → GAME OVER / ENDING → TITLE 以外の遷移は起きない
- **ゲームは必ず終わる**: 3 つの難易度 × 4 名 × 多数のシードで、全部が GAME OVER か ENDING に着く（刻みの上限に届いた割合を測って ADR に書く）
- **難易度の単調性**: 同じランナー・同じシードの集合で、平均の到達した距離が EASY ≥ NORMAL ≥ HARD
- **入力の合法性**: AI のランナーの入力は、いつも人が押せるキーの組み合わせと同じ形（第 2 の操作の経路を作らない）
- **人と AI の入れ替わり**: 遊びのキーを押した刻みから人の入力が効き、決めた秒数押さなければ AI に戻る

## 4. やらないこと

- 施主に聞いてから決めること（音・決めた FR の削除・操作のキー配置の大きな変更）を勝手に入れること
- 外部のゲームエンジン・物理や描画のライブラリを使うこと
- 元のゲームの名前・キャラクター・面の名前・会社名・敵やボスの絵・曲を写すこと
- 不変条件のテストの件数を黙って下げること
