# ADR 0007 — 端末と描画の土台を Swarm から移し、面の窓をカメラで映し、押す・離すのキー入力で人が割り込めるようにする

- 状態: 受理
- 日付: 2026-10-27
- Issue: #5
- 影響する規則: ARC-004 / ARC-005 / ARC-006 / ARC-007 / ARC-011 / SWF-009 / SWF-013 / QLT-001 / QLT-013
- 置き換える範囲: ADR 0004 の「Swarm が Phase 3-2 で足した Terminal の `Synchronization` は、同じ必要が生じた PR で足す」を、この ADR で承認する

## 文脈

Core（ADR 0005）は画面なしで動き、不変条件のテストが緑になった（ADR 0006）。次は画面に出し、人が遊べるようにする（Phase 3-2）。
兄弟の NeNe Swarm は、端末（termios・alternate screen・シグナル・差分出力・256 色への近似・罫線の幅の問い合わせ）と描画の土台、
30 刻み／秒の 1 本のループ、smoke を v0.1.0 まで通している（Swarm の ADR 0007・0011）。Bolt が Swarm と違うのは次の 2 点。

- 面が端末より広い（180 セル × 18 〜 30 段）。どこを映すかを決める必要がある
- 人が遊ぶ（FR-04a・FR-04b）。ふつうの端末は「キーを離した」を送らないので、押しっぱなしで走り、離すと止まる操作がそのままでは作れない

## 決定

### 移植したもの（NeNe Swarm `a660f47`）

| このリポジトリ | 移植元 | 変えたこと |

| `NeNeBoltRender` の `Cell`・`CellColors`・`ColorMode`・`Grid`・`Rgb`・`ScreenSize`・`Segment`・`FrameStyle`・`FrameGlyphs`・`Panel`・`TerminalTraits`・`DisplayOptions`・`ScoreStorage`・`BigFont`・`DifficultyLabel` | `Sources/NeNeSwarmRender/` | 変えていない |
| `Theme` の 12 テーマの名前と色 | `Sources/NeNeSwarmRender/Theme.swift` | Swarm の 11 色の役を替えて当てた（下）。面ごとの地形の色は Phase 3-5 |

| `eng/prove-gates.py` | `eng/prove-gates.py` | 全 target がそろったので、足場をやめて本物のソースに仕込む Swarm の形に移した。公開の証明（P51〜P54）は Phase 4 |

`NeNeBoltTerminal` の標準モジュールに `Synchronization` を足す（`Atomic` のシグナルの旗。Swarm の ADR 0007 と同じ理由）。

### 画面（80 × 24）

- 上端に題の帯、その下に罫線の枠の中の**面の窓（39 セル × 18 段＝端末の 78 桁 × 18 行・1 セル＝2 桁）**、枠の下に 2 行の HUD、下端にキーの帯
- 横に流れるので、兄弟の「左に盤面・右に HUD」をやめ、窓を端末の幅いっぱいに取って HUD を下の 2 行にした（FR-16 の B 案の枠と 2 段の考え方は同じ）
- HUD（FR-10）: 1 行目にスコア・1 位・面・残機・体力のゲージ（10 目盛り）・コイン・パワーアップ、2 行目に残り時間・難易度・誰が操作しているか（`AUTO <名前>` か `PLAYER <AI に戻るまでの秒>`）・キー入力の方式・通算のゲーム数
- キーの帯（FR-15）: `[q] QUIT  [t] THEME …  [d] …  ARROWS MOVE  Z JUMP  X FIRE`。矢印の字形（←→）は端末によって幅が 2 桁になる（East Asian Ambiguous）ので ASCII で書く
- 自機・敵・弾・地形・拾うもの・据え付けは空白のセルの背景色だけで描き、文字を書かない（FR-07・テストで見る）。体の幅は偶数桁にそろえる（自機 2 桁 × 2 行・敵と弾と拾うもの 2 桁・溜め撃ち 4 桁・動く足場 6 桁・ボス 4 桁 × 3 行）
- 消える足場は、見えている間は据え付けの色、消える 15 刻み前から点滅し、消えている間はうっすら跡を残す（覚えて渡る・FR-02b）
- 大きな文字の帯（面の始まり・CLEAR・VICTORY・GAME OVER・ALL CLEAR）は 1 点を 2 桁で塗る

### カメラ（`Camera`）

- どこを映すかは Render が決める（ADR 0004）。状態を持たず、ゲームの状態だけから決まる
- 自機を窓の左から 2/5 に置き（前を広く見せる）、縦は真ん中。面の端では止まり、面の外を映さない（テストで全 4 面の端を見る）
- 横は半セル（8 単位＝1 桁）、縦は 1 セル（16 単位＝1 行）にそろえる。地形のセルが桁と行からずれない。Core の座標を窓の桁と行に直すのはこの型の 1 経路

### キー入力（FR-04b）

- 起動時に Windows Terminal の **win32-input-mode**（`ESC [ ? 9001 h`）を頼む。応じる端末では、1 キーの押す・離すが `ESC [ Vk ; Sc ; Uc ; Kd ; Cs ; Rc _` で届く。応じない端末はこの列を無視し、キーは文字のまま届く
- `KeyDecoder`（Terminal）が両方の形を同じ経路で読み、`KeyEvent`（押した・離した・文字として届いた）にする。win32-input-mode の列が 1 つでも届いたら、その方式で動いていると HUD に出す
- `HeldKeys`（Terminal）が「いま押されているキー」を決める
  - 押す・離すの方式: 押してから離すまで。離したことが届かなくても（窓の外へ注意が移ったとき）、押しっぱなしのくり返しが 1 秒途絶えたら離したとみなす
  - 簡易な方式: 最初の 1 文字は 0.6 秒（端末のくり返しが始まるまで）、くり返しが始まったら 0.12 秒途絶えた時点で離したとみなす
  - 1 刻みの間に押して離した短い打鍵も、次の 1 回は押されていたことにする（跳ぶ・撃つの取りこぼしを防ぐ）
- win32-input-mode では Ctrl+C が SIGINT ではなくキーとして届くので、キーとして読んで終了する
- 端末を戻す列（`restoreTerminal`）の先頭で win32-input-mode を解く。異常終了のシグナルでも同じ列で戻す

### 人と AI の入れ替わり（FR-04a・合成ルートの `Controls`）

- キーとボタンの対応は合成ルートが持つ（ADR 0004）: 矢印＝左右上下・`Z` と空白＝跳ぶ・`X`＝撃つ
- 遊びのキーのどれかが届いた瞬間から人の操作になり、`--hand-back`（初期値 30 秒）なにも押さなければ AI に戻る。押す・離すの方式では押しっぱなしも操作に数える
- 人と AI は同じ `Buttons` を同じ `Session.step` に渡す。`q` `t` `d` は人が遊んでいる間も効く
- 1 ゲームの中で人が 1 度でも操作したら、ハイスコアの名前は `PLAYER`（FR-02g）
- AI は仮の `Autopilot`（右へ走り、前が壁か穴か敵なら跳び、撃ち、梯子があれば上る。ときどき迷って立ち止まる）。本物のランナーとキャストは Phase 3-4

### 色（仮）

Swarm の 11 色を、自機・自機の弾・敵（歩く・跳ねる・砲台）・拾うもの・敵（飛ぶ・結晶）・危険（敵の弾と棘）・岩・ボス・光り・背景に当てた。
梯子・動く足場・消える足場の「据え付け」の色は、Swarm のビームの色が地に対して 3:1 に届かないので、岩を文字の色へ 45% 寄せて作る。
氷は岩を強調の色へ寄せる。どれも地に対して 3:1 以上、自機はどの敵とも RGB の距離 60 以上、画面の英数字は 4.5:1 以上をテストで見る（12 テーマ）。

### 計測（2026-10-27・疑似端末の 80 × 24・シード 1・30 刻み／秒・25 秒）

| 項目 | 値 |
| --- | --- |
| 1 秒あたりの出力 | 約 13.3 KB（Swarm は約 9.5 KB。横に流れると地形のセルが毎刻み書き直しになる） |
| 1 回の読み出しのバイト数 | 中央値 345・95% 点 1,047（疑似端末の読み出しは 4,095 バイトで切れるので、最大は測れていない） |

## 強制

- **active**: `make check` の `smoke` 段（`q`・Ctrl+C・SIGTERM・SIGSEGV・大きさの変更で端末が戻ること・`t` と `d`・TITLE → PLAY・ASCII の枠への切り替え・
  矢印キーで人の操作に替わり簡易な方式と出すこと・win32-input-mode の列で人の操作に替わりその方式と出すこと・その列の `q` と Ctrl+C で終わること・起動オプションの拒否）と、
  証明 P49（端末を戻す列を壊すと smoke が落ちる）
- **active**: Render のテスト（80 × 24 に入る・キーのヘルプと題が常にある・面の窓の色のセルに文字が無い・カメラが自機を窓に入れ面の外を映さない・HUD の操作者とキー入力の方式・
  小さい端末・ASCII の枠・12 テーマのコントラスト）と Terminal のテスト（キーの読み取り・押されているキーの決め方・差分出力・256 色）
- **planned**: Windows Terminal の実機で win32-input-mode が WSL の中のプログラムまで届くか・ちらつき・見え方（Phase 3-3 の画面写真と手での確認。疑似端末は Windows Terminal の代わりにならない・QLT-013）

## 結果

- 画面が出て、キーで遊べる（疑似端末で確かめた範囲）。TITLE → PLAY → GAME OVER / ENDING → TITLE を回し、地形・消える足場・敵・弾・拾うもの・ボス・自機が窓に収まる
- 簡易な方式では、離してから最大 0.12 秒（くり返しが始まる前は 0.6 秒）走り続ける。押す・離すの方式が使えない端末の制約で、HUD に方式を出して分かるようにした
- 仮の色では、テーマによって敵の 2 色が似る。Phase 3-5 で面ごとの地形の色（結晶の洞窟は青と水色・FR-12）と専用の色を決める
- 失うもの: 大きな端末でも 80 × 24 の配置のまま（左上に寄る）。大きな端末の配置は Phase 3-5

## 却下した選択肢

| 選択肢 | 却下の理由 |
| --- | --- |
| 兄弟と同じく左に盤面・右に HUD | 窓が 26 セル幅になり、横スクロールで前が見えない。跳ぶ先の穴や敵が画面に入るのが遅すぎる |
| カメラを Core に置く | 当たり判定に関係しない値がゲームの状態に入り、決定性のテストが見た目の変更で壊れる（ADR 0004） |
| カメラに状態を持たせ、ゆっくり追わせる | 見た目のための状態が合成ルートに増える。いまの単純な追い方で窓から自機が外れないことをテストで見られる。滑らかさは実機で見てから |
| kitty の keyboard protocol（`CSI > u`）で押す・離すを受け取る | Windows Terminal が施主の環境（WSL2＋Windows Terminal・FR-09）の端末で、win32-input-mode はその端末自身の方式。どちらにも応じない端末は簡易な方式に落ちる |
| 簡易な方式で「1 文字＝1 刻みだけ押す」 | 走るのがくり返しの速さ（毎秒 30 前後）に縛られて途切れ、跳ぶ高さも決められない |
| 押しているキーの決め方を合成ルートに書く | 端末の性質（くり返し・離したことが届かない）の知識なので Terminal に置き、テストを書ける場所にした。キーとボタンの対応だけを合成ルートに置く（ADR 0004） |
| 人が触ったゲームのハイスコアを残さない | FR-02g は「ランナー名か PLAYER」。人の記録も残す |
