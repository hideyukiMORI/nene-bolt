# ADR 0006 — 不変条件のテストでゲートを組み、4 面それぞれから release 構成で 600 ゲームを回す

- 状態: 受理
- 日付: 2026-10-27
- Issue: #3
- 影響する規則: QLT-001 / QLT-008 / SWF-008 / SWF-016

## 文脈

アクションゲームには公表値が無い。Swarm の ADR 0006 と同じく、REQUIREMENTS 第 3 節の不変条件を「1 ゲームを最後まで回し、刻みごとに見る」と
「手で作った場面で 1 つの経路を見る」で確かめる。本物のランナー（Engine）は Phase 3-4 で入るので、テストの中にだけ 2 つのランナーを置く。

- `random`: 6 つのボタンの組を乱数で選び、20 刻みごとに選び直す
- `forward`: 右へ走り、前が壁か穴か敵なら跳び、撃ち続け、梯子があれば上る（乱数を使わない）

テストのランナーは下手で、1 面から始めると 4 面に届かない。そこで**4 面それぞれから始めたゲーム**も回し、後ろの面の地形と敵とボスの部屋も通しのゲームで見る。

## 決定

1. 不変条件はテストで守り、`make check` の `test` 段（`swift test -c release`）で回す（Swarm と同じ）
2. **始める面 4 × 難易度 3 × テストのランナー 2 × シード 25 = 600 ゲーム**を最後まで回し、刻みごとに次を見る（`InvariantTests`）。件数を黙って下げない
   - 範囲: 自機が固い地形のセルと重ならない・面の左右の外へ出ない・コイン（0〜99）・体力（0〜10）・パワーアップ（0〜2）が範囲の中・自機の弾が画面に多すぎない
   - 数の保存: スコアの増え方は出来事の得点の合計に等しい（減らない）・残機は「1 機失った」「1UP を拾った」「コイン 100 枚」の出来事でだけ動く
   - 必ず終わる: 600 ゲームすべてが終わり、刻みの上限（36,000）に届いたものは 0
3. 決定性: 2 つのランナー × 2 つのシードで、同じシードの 2 回が刻みごとに同じ状態と同じ出来事の列になる。違うシードは違うゲームになる。終わったゲームは変わらない
4. 難易度の単調性: 同じランナー・同じ 25 シードの**合計の寿命（刻み）**が EASY ≥ NORMAL ≥ HARD。`Tuning` の各値も、4 面で難易度と面について単調。
   REQUIREMENTS 第 3 節の「平均の到達した距離」は、テストのランナーが同じ所で詰まると差が出ないので、寿命に読み替えた（REQUIREMENTS を同じ PR で直した）
5. 手で作った場面（`PhysicsTests`・`CombatTests`・`ProgressTests`・`MapTests`・`SceneTests`・`HighScoreTests`）で、床を突き抜けない・跳ぶ高さ・氷・梯子・コンベア・
   動く足場・消える足場（間隔どおり・乗っている間に消えたら落ちる・中に現れても閉じ込めない）・壁・棘と穴・撃つ・3 発まで・溜め撃ちの貫通・踏む・踏めない砲台・
   無敵・体力切れ・割れる結晶・ボス戦から ENDING・中間地点・ゴールと時間のボーナス・時間切れ・コイン 100 枚・場面の遷移を 1 つずつ見る

## 計測（2026-10-27・release 構成・シード 0〜24）

30 刻み／秒で 1,800 刻み＝ 1 分。`forward` は乱数を使わないので、シードによらず同じゲームになる（敵の出方の乱数だけが違い、通る道は同じ）。

| 始める面 | ランナー | EASY 平均 | NORMAL 平均 | HARD 平均 | 時間切れで失った機（NORMAL・25 ゲーム） | 刻みの上限 |
| --- | --- | --- | --- | --- | --- | --- |
| 1 | random | 10,657 | 10,608 | 10,579 | 28 | 0 |
| 1 | forward | 2,133 | 2,133 | 2,133 | 0（1 面を抜け、2 面の消える足場で落ちる） | 0 |
| 2 | random | 7,434 | 7,047 | 5,610 | 13 | 0 |
| 2 | forward | 1,066 | 1,066 | 1,066 | 0 | 0 |
| 3 | random | 1,731 | 1,730 | 1,553 | 0 | 0 |
| 3 | forward | 528 | 528 | 492 | 0 | 0 |
| 4 | random | 12,658 | 10,202 | 4,395 | 38 | 0 |
| 4 | forward | 1,155 | 954 | 837 | 0 | 0 |

- 刻みの上限（`.timeLimit`）に届いたゲームは **600 中 0**
- テストのランナーはどちらもボスを倒せない。ボス戦から ENDING までは手で作った場面（`CombatTests`・`SceneTests`）で見る
- テスト全体（55 件・600 ゲームと決定性と単調性）は release 構成で約 1 秒
- 1 ゲームの長さの目安（Q13・NORMAL で平均 4〜6 分）は、本物のランナーで Phase 3-4 に測る

## 強制

- **active**: `make check` の `test` 段。negative proof に「テストの期待値を 1 つ変えると `make check` の中の `swift test` が落ちる」証明（P48）を足す
- QLT-008（振る舞いの変更はテストを伴う）は planned のまま。テストを足したかは機械が見ない

## 結果

- 地形に埋まる・閉じ込められる誤りは、画面に出す前にテストで見つかる（600 ゲームの刻みごとに、固い地形のセルと重なっていないかを見る）
- `forward` が乱数を使わないので、その 25 シードは同じ道の 25 回になる。敵の出方の違いは見ているが、道の違いは `random` だけが作る。本物のランナーが入ったら、その 4 名も不変条件のゲームに足す（Phase 3-4）
- 失うもの: テストのランナーが通らない場所（例: 2 面の上の方・4 面の後半）は、通しのゲームでは見ていない。そこは各面から始めるゲームと手で作った場面で補う

## 却下した選択肢

| 選択肢 | 却下の理由 |
| --- | --- |
| 1 面からだけ回す | テストのランナーが 2 面より先へ行かず、3・4 面の地形・コンベア・棘・ボスの部屋が通しのゲームに入らない |
| シードを 100 にして 1 面からだけ回す（Swarm と同じ 600 ゲーム） | 上と同じ理由。件数は同じ 600 で、面の広がりを取った |
| 難易度の単調性を「到達した距離」で見る | `forward` は難易度によらず同じ所で詰まり、距離が同じになる。寿命なら敵の強さの差が出る（4 面で 1,155 ≥ 954 ≥ 837） |
| 本物のランナーができるまで不変条件のテストを待つ | 地形と当たり判定の誤りが画面と AI に混ざってから見つかる。Swarm と同じく Core だけで先に緑にする |
